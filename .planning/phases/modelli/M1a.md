# M1a — catalog and complete pin

Implemented additively on bridge 1.39.0, source checkpoint cc51d9f; existing provider enum, legacy routing DTOs and budgets are unchanged. This bridge declares metadata and validates choices; it does not discover providers, install adapters, execute model calls or apply a runtime configuration. Provider/model fixtures are synthetic.

The catalog is scoped to a management agent, function and exact provider/model/protocol/registered-adapter descriptor. It separates known access from runtime support, includes source/sourceVersion/version and observation/expiration, rejects duplicate descriptors and unpaired timestamps, and carries only optional producer-attested limits. Missing limits are unknown. URLs and credential fields are rejected. Canonical server-boundary normalization maps claude to anthropic and gemini to google without changing legacy DTOs. Transcription has a distinct function/protocol. News, recap and document uses will be distinguished by stable slots in M1b, not guessed model names.

Capability settings retain automatic tier routing or enforce a complete pin over standard/advanced/reasoning and fallback. Validation requires the explicitly addressed agent, current fresh catalog, exact function/descriptor, access, runtime support and required tools/stream/structured output. Memory extraction requires structured output. Producer validation must also impose the capability's own requirements; the browser cannot weaken those requirements.

Public exports in model-router and root: ModelCatalogSchema, ModelLimitsSchema, ModelDescriptorSchema, CapabilityModelSettingsSchema, normalizeModelProvider, validateCapabilityModels and their inferred types. HTTP exports: internalAgentModelCatalogContract, agentModelCatalogPath; metadata GET /internal/agents/:agentId/models/catalog reuses management params and the canonical authentication header. No endpoint handler or provider availability is claimed here.
